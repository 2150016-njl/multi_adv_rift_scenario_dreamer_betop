# P1/P2 身份冲突：v2 取证与运行指南（2026-10-19）

## 事实与边界

本版本只修正辅助启动器 `fixed_inputs()` 对重复 `scene_id` 的无诊断硬阻断。**没有修改** P1 冻结源码、RIFT、原始 95 manifest、snapshot 或 CARLA `s` / spawn 判定。`inputs` / `p2-export` / `report` 不连接 CARLA，`run95` 则直接调用已存在的真实冻结审计器，会切换多个 Town 并生成/销毁 actor，仅限已获独占使用权的实例。

95 条 manifest 可以使用不同的 `record_index + snapshot_path + snapshot_sha256` 独立绑定记录；`scene_id` 非唯一时必须保留来源歧义。v2 允许**无损收集证据**，但严格禁止将来源未证实的重复 scene_id 判为科学验收 PASS。重复 record_index / 重复 snapshot 文件路径 / SHA 不一致，仍直接退出 2。`scene_id :sparse0` 是否合理仍待实际生成链证明。

期望 `ALL_P1P2_V2_OFFLINE_INTEGRATION_TESTS_PASS_NOT_CARLA`。**这是合成数据离线测试，不是实际 95 manifest 或 CARLA PASS。** 本地用 Python 3.13 完成实际测试；服务器 Python 3.8 须自行运行此入口确认。

## 1. 首先直接显示真实 95 条冲突——不要启动 CARLA

```bash
TOOL="$ROOT/hv_v8/p1p2_pipeline_v2.py"
INPUT_REPORT="$BASE/p1_inputs_95_identity_v2_$(date +%Y%m%d_%H%M%S)_$$.json"
"$PY" "$TOOL" inputs --root "$ROOT" --output "$INPUT_REPORT"
printf 'P1_REAL_INPUTS_V2_RC=%s\n' "$?"
```

观察 `P1_TOWNS`（必须是实际分布而非测试合成 `Town15:95`）、`P1_SCENE_ID_UNRESOLVED`、`P1_DUPLICATE_SCENE_ID_GROUPS`（含双方 `ordinal`、`record_index`、snapshot 路径与 SHA）。这些字段为原始证据，不自动判定它们是否为同一个真实场景。只有这一步真实扫描完成才考虑下一步。

## 2. 不连接 CARLA 导出 P2 原始条件及 GT 分离数据

```bash
P2_OUT="$BASE/p2_baseline95_v2_$(date +%Y%m%d_%H%M%S)_$$"
"$PY" "$TOOL" p2-export --root "$ROOT" --output-dir "$P2_OUT"
printf 'P2_EXPORT_V2_RC=%s\n' "$?"
```

导出 `p2_conditions_95.jsonl`、`p2_gt_labels_95.jsonl`、`provenance.json`；重复 scene ID 与 `:sparse0` 不会被删减或自动清洗，另列 `scientific_identity_verified=false`。所有记录必须按 `ordinal+record_index+manifest_scene_id+snapshot_scene_id` 查阅，不允许只用 scene_id join。此导出不等于固定 110 个前方 GT、不等于训练 ready。

## 3. P1 完整 95 条真实校准（可选，先审查身份冲突）

前提：上一步实测确认是独立 `record_index` 与 snapshot，不是重复索引/文件；CARLA 31120 为当前项目**独占**；已确认可以在其中加载 Town 和修改 actor。新版本依旧有已知 provenance 未解决，因此完整审计仅收集真实证据，**不表示最终 P1 PASS**。

```bash
RUNLOG="$BASE/p1_full95_v2_$(date +%Y%m%d_%H%M%S)_$$.log"
"$PY" "$TOOL" run95 --root "$ROOT" --python "$PY" \
 --host 127.0.0.1 --port 31120 --ack-dedicated > "$RUNLOG" 2>&1
RC=$?
printf 'P1_FULL95_V2_EXIT=%s\nP1_FULL95_V2_LOG=%s\n' "$RC" "$RUNLOG"
grep -E '^P1_FULL95_(RUN_DIR|AUDIT_OUT|LOG|PROCESS_EXIT|RESULT_DIR)=' "$RUNLOG"
tail -n 30 "$RUNLOG"
```

只有出现 `P1_FULL95_RUN_DIR=...` 才算启动器真正建立了运行目录；出现 `P1_FULL95_PROCESS_EXIT=0` 仅表示原冻结审计进程成功，**不得跨过 provenance / 物理可行性 gate**。

## 4. 完整或部分审计账本（只读、无需 CARLA）

```bash
RUN_DIR=$(sed -n 's/^P1_FULL95_RUN_DIR=//p' "$RUNLOG" | tail -n 1)
if [ -n "$RUN_DIR" ]; then
  REPORT_DIR="$BASE/p1_95_v2_ledger_$(date +%Y%m%d_%H%M%S)_$$"
  "$PY" "$TOOL" report --root "$ROOT" --audit "$RUN_DIR/audit" --report-dir "$REPORT_DIR"
else
  echo 'NO_REAL_AUDIT_RUN_DIR; report not attempted'
fi
```

保留真实拒绝、UNKNOWN；`native_95_verified` 在来源重复/后缀身份未验证时仍 false。`p1_model3_legal_training_dataset_ready` 始终 false，因为当前审计未证明完整三维物理合法性。

## P2 真实拓扑的正确解释

用户此前实测 Town15：`P2_GRAPH_SEGMENTS=1038 LANE_KEYS=918 DIRECTED_EDGES=1044`；`GT_TARGETS=26 CONNECTED=14 NOT_CONNECTED=12`。这是 `p2_topology_probe.py` 在其中 12 条记录上的图可达性**诊断**，不是固定 110 GT 的完整 approach recall，也不说明 12 个一定非法/无交互。应把未连通样本进一步区分为映射错误、后继/connector 缺失、路径跳数限制、真实冲突锚点不在图内等类别。不要在这个阶段将 GT 信息泄漏给在线图构建。

## 仍需解决而非隐藏

- 重复 manifest scene_id 与 ordinal 50 `:sparse0` 的来源绑定需从真实 manifest 生成链核查；v2 **没有**替代该 provenance 工作。
- P1 95 条真实全量尚未跑完。
- 即使 raw spawn 拒绝是确定负例，也不自动等于所有历史 GT 为 Model3 合法正例；occupancy unknown 必须保留。
- P2 的完整有向 approach/GT recall / P3 解码门槛仍未通过。
