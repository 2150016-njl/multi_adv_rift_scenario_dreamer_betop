# 前方地图约束与原生 route conflict：主线诊断批次

## 任务与已有证据

任务是单次输出未经修正的 CBV 初始状态，在当前 FOV64 的 `0<x<=32, |y|<=32` 内，满足地图/占位约束，并具有初始 RIFT native route conflict。至少一辆与双车成功分别报告。正常 attention 排序和最终 green 激活是后续验证层。

已有全量离线对照是同一 V3 test 的 3727 条、每模型 7454 辆：GT 有 36.01% 的目标在 x<=0，V2 为 41.02%，V3 为 30.87%。因此历史目标域与当前前方任务不一致。前方车辆距所有已提供中心线的并集超过 5m：GT 为 0%，V2 20.11%，V3 24.43%。这是明显几何偏离证据，但不是道路 polygon 判定，不能叫真实 off-road rate。

V5 的 chart roundtrip 准确，只能证明进入 chart 的状态可表示；519/16362 的训练场景保留数包含多个筛选条件，不能直接当作纯候选覆盖率。需要本批统计真实前方 native-positive 的候选覆盖。

原始研究日志中的结论是历史实验解释，不能代替本批的 GT/native 校准。尤其不能凭“AE 已排除”跳过 decoder/raw-state oracle，也不能凭 NuPlan 的背景分布接受任意不满足当前道路和交互条件的目标 CBV。

## 批次内容与统计单位

1. 从既有 160509 配对审计中验证 unique partial 的 SHA 和原始选择分区，保留排除项。该次为 100 请求中的 95 个无歧义记录，不冒充全测试集。
2. 对已绑定 snapshot 按 physical replay 指纹去重，原始车池检查和完整原始车队 spawn/physics 不重复计算 sparse copies。不是重新扫描 54,936 文件。
3. 原始车池运行 snapshot/native/spawn/physics，保留真实车型、原始姿态与速度、全车辆占位。零个 native positive 只表示该已保存车池没有正例，不表示不存在其他可行初始状态。
4. V3 S1 根据原始 record index 重新绑定到 V2 的同一 source、GT、ego route、condition 和 observed IDs。检查 dataset/source SHA、sample index=0、唯一性和状态匹配；缺失或错配不悄悄取交集。
5. GT/V2/V3 主实验的 physical context 是全部原始非目标车辆；模型输入仍是历史 condition。生成车辆替换目标车辆，保留其余真实车辆。避免稀疏 observed context 把真实占位障碍删掉。
6. V2/V3 另跑 manifest 稀疏 physical context 的 snapshot/spawn 对照，以定位缺失交通信息的影响。它的成功率不能代替完整交通中的成功率。
7. 每阶段固定选择后才按 Town 排序，减少地图重载；不改变原始 record index 或样本集合。每条记录打印进度。
8. 原生布尔判断保持原算法。NaN/Infinity 数值观测写 null 并记录字段和原值种类，不能当零，受影响数据不能宣布完整验收。
9. 单个实验阶段失败后，其他独立阶段继续收集证据；最终状态仍为 incomplete/nonzero。失败、未写出的计划记录均保留在统计分母中，未知单列。

自动生成 experiment/analysis.json：逐 cohort 的 true/false/unknown、首次失败或未知步骤、原生拒绝原因、candidate/approach 覆盖、占位、spawn、polygon 和物理汇总；保存 V2/V3 成对结果及 episode block bootstrap 区间。重复 sparse copies 或相邻帧不能当独立样本；不足两个 episode block 不给置信区间。GT 重复回放单列以检查实验一致性。

原始字段仍在每阶段 jobs.jsonl、rows.jsonl、summary.json。程序执行完不等于模型验收通过。

## 如何决定下一步

| 观察 | 解释与行动 |
| --- | --- |
| GT preview/native 大量失败、route resolution 错误或保存配置不一致 | 先校准 Town、地图版本、初始化时刻、route waypoint 身份、识别配置及已有 CBV 容量。检查 saved/native disagreement，不能先归因生成模型。 |
| GT 原始车型/完整车队无法 raw spawn | 先分车辆型号、碰撞占位、高程、尺寸、历史 pose、是否已发生碰撞统计。GT 静态原状态是否可重建是生成比较的基准。 |
| GT 前方 native-positive 存在，但 V5 candidate 不支持 | 候选空间/筛选器有漏解；先重建 conflict approach，停止在该筛选集合上继续堆 loss。保留分 Town、junction、交通密度的覆盖与未知分母。 |
| GT 同条件可行，生成输出常在后方或远离可行驶区域 | 条件到初始状态的生成问题。先检查 AE/raw-head oracle，再比较 teacher-forced 与 condition-only S1；修改训练输出域和表示。 |
| 稀疏上下文可 spawn，完整交通明显下降 | 条件缺失占位信息；应保留 actor tokens/observability masks，并补充完整交通条件训练。不能用删交通或推理后挪车获得成功。 |
| 地图、native、raw spawn 通过，但 physics 出现碰撞或不稳 | 查实际车型包围盒、z/层级、初速度执行、pitch/roll；做短时落地及速度测量。该 probe 不是历史 episode 或完整控制验证。 |
| 初始候选条件都过，最终 green 接管仍差 | 再查 attention 排序、识别 warmup、容量和正常控制。当前批次不能证明这一层。 |

## 改进的实施顺序

### 先修条件与目标域

- 保留有向 predecessor/successor、lane/connector 身份、width/XYZ、高程层级，不用 XY 接近伪造连接。
- 从 ego future route 的锚点构造目标 approach，沿有向图向上游回溯；用原生 preview/route 和距离差对候选校准。不能把“ego 当前附近车道”当作冲突 approach。
- 生成条件仅来自在线可得 map/ego route/observed actors；真实 target 的 interaction trace 只作训练监督/覆盖 oracle，不能泄露给生成条件。
- 保留 actor tokens、类型和实际/近似车框来源、观测缺失 mask。明确训练和输出均为前方域，不能只在评估时删除后方输出。
- 固定车型生成时，应使用真实 blueprint 的物理尺寸评估；自由预测的 length/width 误差另列，不把它自动当实际 spawn 车框。

### 再补数据

按 Town、拓扑、初始化 frame、交通密度、稀疏程度分层补缺口。保存 source SHA、actor ID/token、地图版本和有向拓扑，按 episode/route group split。保留正负原始车池和搜索证据。

“候选中未找到解”与“已证明无可行解”分开：记录搜索域、候选数量、地图/拓扑缺失、约束及排除原因，状态用 `found / not_found_within_support / unknown`。有限候选和单次原车池未覆盖连续状态空间，不能给不可行性证明。

### 最后训练与闭环

先验证 GT->表示->raw state oracle 和候选支持，再训练 conflict-conditioned 的联合双车输出。前方范围、车道内坐标、高程/车型约束应作为可解释的模型参数化与训练目标，而不是采样后 clamp/snap/retry。严格 S1、相同路线/seed/交通条件下比较 baseline 与改版，保留所有失败请求。

候选建模消融至少分开：旧几何；有向拓扑+width/z；加入 conflict approach；加入 actor tokens。改变一项时保持数据选择、训练预算和 S1 评估口径一致。不要把所有改动合并后只报一个平均位置误差。
