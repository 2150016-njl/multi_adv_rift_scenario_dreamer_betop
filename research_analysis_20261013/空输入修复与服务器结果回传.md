## 运行

同步这五个文件到服务器对应位置：

- audit_hv_snapshot_experiment.py
- build_hv_snapshot_audit_manifest.py
- hv_audit_inputs.py
- run_hv_snapshot_diagnostics.py
- scenario-dreamer/high_value_init/native_state_audit.py

```bash
export ROOT=/zeron-vepfs/tjqc/njl/multi_adv_rift_scenario_dreamer_betop
export PY=/zeron-vepfs/tjqc/njl/conda_envs/rift/bin/python
cd "$ROOT"
"$PY" run_hv_snapshot_diagnostics.py --with-native --with-spawn --port 31000
```

需要专用、空车辆、无其他客户端推进 tick 的 CARLA。实验会切换地图，并临时修改同步设置后恢复。本机没有 CARLA，native/spawn 尚未实机验证。

入口从 test 同目录 summary.json 自动读取 RAW；工程迁移时尝试当前 ROOT 下同名目录；仍不存在就停止并打印路径。可以用 --raw /actual/collection/path 指定真实迁移目录。不能使用无关快照凑配对。

自动新建 ASCII 时间戳输出目录，保存 run.json 与各阶段日志，任一步失败立即停止。阶段是：原始 pool 前100文件 → test固定前100记录与 V2 S1 严格配对（扫描完整 RAW）→ 成对 snapshot → 成对前20 native → 同一前20 spawn。

pool前缀与test配对前缀不是同一批场景，不能直接相减。native/spawn对固定manifest前缀比较，不重新采样。没有CARLA时运行不带 --with-native/--with-spawn 的入口即可完成前三阶段。

默认100/20是排错规模；扩大可加 --max-records 1000 --native-records 100。子目录名字沿用100/20，实际样本量以 run.json、summary.json 为准。固定前缀不能代替完整test的版本评价。

## 覆盖边界与分析口径

支持：原始池前方saved positive与unknown区分；候选几何/上游/anchor覆盖；同context的GT/生成2D OBB占位；真实CARLA非投影center/2m preview、None与False比较、lane width；隔离provider/cache执行原生候选函数，记录交互点、目标路径、距离差和拒绝阶段；GT原始车型/pose/velocity请求与生成车型/raw spawn命令、单次接受、实际box记录。

并非完整：静态占位是2D近似，未实现整车道路polygon包含或完整3D碰撞；spawn是零tick接受实验，不能验证落地稳定性、速度执行或动态episode；native候选不等于attention排序/最终green接管。缺少saved容量上下文时记录empty_slots_assumed，不能声称严格复现历史识别器状态。生成没有保存spawn命令时，z按既有nearest-road高度规则重建，不代表复现了历史命令。

GT/生成使用相同context、FOV、地图查询、native规则和占位算法；GT保留真实车型，生成使用Tesla，车型差异单独记录。selected_gt只代表训练选中目标，raw_pool另保留完整原始周车，避免把选中目标覆盖率误当全池覆盖率。

先看配对passed、planned_jobs、native_error_jobs和unknown分母，再比较GT与生成的前方道路/preview/native/占位/整组spawn通过率；按Town分层。GT native无法复现时先查map/config/mode/route/容量；原始前方positive丰富但候选覆盖低则先修candidate；生成主要败在preview/route则修支持域和交互条件；native好而spawn差则查box、占位、z、静态障碍。20场景只做故障定位，后续扩大样本并按episode/route分组统计。
