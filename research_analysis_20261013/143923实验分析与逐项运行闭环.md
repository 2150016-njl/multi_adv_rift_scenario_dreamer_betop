## 修复与验证

- 根据 context_sampling.sparse_context_copy_index 识别真实 sparse 后缀，同时保持每条 S1 对应原始 dataset record index。仅有类似后缀而无元数据时不随意剥离。
- 继续核对 GT、ego、route、观测 context；新增原 builder 的 FOV/距离排序、目标 rank、原 positive 数量、稀疏 kept indices 校验。
- 对不同文件的 replay 输入、全周车、地图、容量上下文和 saved labels 做精确指纹。只有这些内容完全一致才归并为 replay-equivalent sources，保留全部路径/SHA，不宣称找回唯一历史路径。实质不同继续拒绝。
- 新增 ambiguity_details、逐记录 mismatch、最多20份歧义源 snapshot 副本。下次不需要再靠只有汇总数字的报告猜原因。
- V3 builder 新产物记录 source_snapshot.path/sha256/frame/worker。旧数据无法凭空补回精确来源，不修改已有test或生成输出。
- 所有整场比例保留 planned 分母；缺失 cohort 或 unknown 不产生虚假的完整成功率。

本机43项 CPU/内存测试通过，覆盖 sparse 配对、provenance、三维高架分离、整车越界、道路中间空洞、图节点裁剪重排、physics sensor失败、真实识别调用次数及attention推理次数。新增脚本通过Python编译和Bash语法检查；launcher参数还对照实际run.py parser验证，明确指定attention，校验XML route IDs。

## 当前逐项能力与边界

| 要求 | 代码与验证口径 |
| --- | --- |
| 原始前方positive池 | 已实测；raw_pool保留完整序列化周车，不只看训练选中目标 |
| 道路/preview | native支持真实非投影center、原生2m preview、None/False比较、width和原生route；待服务器执行 |
| 候选覆盖 | 成对输入使用历史condition；raw缺地图可用 --enrich-map 补充实时OpenDRIVE地图，单独标注为fallback，不能冒充历史模型输入 |
| 有向approach覆盖 | v6_condition按真实Waypoint.next导出pred/succ，回溯ego route可达车道，另统计native positive的V6支持覆盖 |
| GT/生成同口径占位 | 同context/同规则；snapshot二维近似，spawn使用实际蓝图offset/pitch/roll/height做15轴三维OBB相交 |
| 整车道路polygon | spawn按实际box在raw请求pose的完整XY投影检查宽度/高程分层lane ribbon的union，含中间空洞检查；按1m采样，非Unreal精确road mesh |
| 静态障碍 | get_level_bbs的三维OBB保守交叠，分类查询异常记unknown；外包围盒交叠不等于mesh碰撞 |
| GT原始状态/raw spawn | 保存原type/xyz/yaw/pitch/roll/velocity请求，单次spawn，无重试/吸附/状态修正；历史属性/physics-control不全，不能称逐物理参数原样恢复 |
| 速度/落地/碰撞 | 新physics模式独立推进tick，记录frame快照速度误差、tail z变化、pitch/roll、真实collision sensor事件；默认20tick、0.05s/tick，无控制/纠正 |
| attention/green/完整在线episode | strict launcher运行正常RIFT pipeline；新增观测日志记录跳过门控、现成候选/attention/selected，不额外识别、不改变排序；green仍是后续时刻证据 |
| 历史episode逐帧精确回放 | 旧snapshot没有完整历史轨迹、行人、信号灯时序和控制，无法从这些文件恢复；physics probe和新online episode都不能冒称历史精确回放 |

道路外不应凭“中心线距离>1.75m”一票否决：这是旧proxy，既没用真实lane width，也没考虑车道/路口/高程。需分别记录center、preview、整车道路覆盖、占位、native interaction与spawn。道路中心/preview通过与整车Driving覆盖不是同一条件。本工具给出严格整车Driving覆盖指标，工程上是否允许车身越界，应由目标场景规范决定，不能从NuPlan预训练分布直接推导CARLA可用性。

collision sensor事件是真实物理证据；有限tick内没有事件不是所有mesh无碰撞的证明。静态level box和road ribbon仍是明确标注的几何诊断。原始GT不能复现时先排查地图/配置/route/车型/容量上下文，不能直接归因模型。

### 0. 同步与代码检查

将 hv_snapshot_followup_patch.zip 上传工程根目录，然后：

```bash
export ROOT=/zeron-vepfs/tjqc/njl/multi_adv_rift_scenario_dreamer_betop
export PY=/zeron-vepfs/tjqc/njl/conda_envs/rift/bin/python
cd "$ROOT"
unzip -o hv_snapshot_followup_patch.zip
"$PY" -m unittest test_hv_snapshot_experiment test_hv_snapshot_followup test_hv_runtime_audit.TestEvidencePhase -v
```

包内只有代码、测试和本说明，没有模型权重或数据。原有结果目录保留。

### 1. 先复核旧前缀配对

```bash
"$PY" run_hv_snapshot_diagnostics.py
```

自动生成新的 snapshot_audit_时间戳目录。必须看到 requested_records=written_jobs=100、passed=true才能将该前缀用于成对实验。如果仍有真正歧义，上传新的 .audit.json、.partial.jsonl、.debug_snapshots/ 和 logs；不要手改passed、放宽阈值或选任意源继续。

### 2. 原始池真实道路/native，可独立于配对运行

先启动专用CARLA，端口31000。给客户端提供与服务器版本一致的PythonAPI：

```bash
export CARLA_ROOT="$ROOT/carla"
CARLA_EGG=$(find "$CARLA_ROOT/PythonAPI/carla/dist" -maxdepth 1 -name 'carla-*.egg' -print -quit)
export PYTHONPATH="$ROOT/RIFT:$ROOT/scenario-dreamer:$CARLA_ROOT/PythonAPI/carla:$CARLA_EGG:${PYTHONPATH:-}"
export RAW="$ROOT/data/hv_init/rift_labeled_phase7_v2_uncovered_routes_seed0_7"
export RAW_OUT="$ROOT/data/hv_init/eval/raw_native_$(date +%Y%m%d_%H%M%S)"
"$PY" audit_hv_snapshot_experiment.py \
  --input-dir "$RAW" --mode native --max-records 100 --enrich-map \
  --host 127.0.0.1 --port 31000 --load-maps \
  --recognition-config "$ROOT/RIFT/rift/cbv/recognition/config/rule.yaml" \
  --recognition-mode eval --sampling-resolution 1.0 --output-dir "$RAW_OUT"
```

这个阶段不需要配对完成；回答原始池saved positive能否native复现、真实preview是否有效、V5与有向approach支持域差在哪。fallback覆盖评估的是实时地图条件，历史V3条件另在成对实验中保留。

### 3. 成对 native / spawn / physics 全部运行

```bash
"$PY" run_hv_snapshot_diagnostics.py \
  --with-native --with-spawn --with-physics --probe-ticks 20 --port 31000
```

默认100条配对、20条成对CARLA排错。pool_native100另外检查原始池100条。spawn是零tick，physics另起一组从原始请求重新spawn后推进，不重用已经移动的车辆判断初始成功。

physics.frames记录每tick实际速度/pose；measurements记录首tick速度误差、最后5帧z变化、pitch/roll及碰撞次数。geometry_3d记录初始请求位置的实际box、整车polygon、peer三维交叠与静态box风险。GT和生成各有自己的cohort，context一致。

summary的joint_*是“context完整+raw spawn接受+前方+初始native+整车采样道路覆盖+peer三维不交叠”的联合指标；静态mesh不在此定义内。target_spawn_requests与accepted保留spawn失败分母，不能只对成功spawn的车辆报性能。静态查询异常、速度观测缺失均不能记作通过。

### 4. 扩大并分层，减少前缀偏差

```bash
"$PY" run_hv_snapshot_diagnostics.py --selection stratified \
  --max-records 100 --native-records 100 \
```

当前本地test实际分层结果：100个不同基础时刻、15个episode、Town12/15/13/11/04分别29/26/28/5/12条；前20条也跨5个Town。保留原dataset index去取原S1，不重采样生成输出。该选择用于诊断覆盖，不是按原分布加权的全test性能；最终版本比较仍要完整test，并按episode/route聚类统计。

输出子目录沿用100/20名字，实际数量以run.json/summary为准。

### 6. 正常attention与green的在线测试

```bash
cd "$ROOT"
GPU=0 ROUTES=28243,24333 SEED=0 \
  bash RIFT/scripts/run_hv_strict_diagnostics.sh
```

这里28243/24333是XML route ID，不是dataset中的route_index=19/27。脚本顺序运行V2/V3，每episode仅一个初始请求，不rolling、不隐藏现有车辆、不靠审计强制注册CBV；关闭existing-positive预筛以保留全部请求分母。两方法保持相同route/seed，其地图坐标模式按原版本保留。

它会自行启动另一个CARLA，默认base port33000，与31000审计服务分开。root启动时由riftuser运行CARLA。输出在 data/hv_init/eval/strict_attention_时间戳/{v2,v3}/，包括runner退出码、one_shot_audit、完整dump、lifecycle和statistics。

normal_recognition_step日志可区分：warmup_le_25、odd_step、capacity_full、候选不成立、attention未选中、最终正常激活。one_shot_audit分别记录actual recognition actor-step次数及最终green。actor-step不是独立场景，不能拿其比例充当场景成功率。runner未正常完成时green率为null。此实验重新生成S1并运行新episode，不冒充保存S1或旧GT episode重放。

### 7. 后续采集：先小规模覆盖，不先扩同类positive

```bash
cd "$ROOT"
GPU=0 SEED=0 bash RIFT/scripts/run_hv_collection_diagnostics.sh
```

默认XML每个Town取一条路线，真实背景强度0.2/0.6各一轮，每episode采集frame0至40（1秒间隔）。这是小规模覆盖探针，并非已经补全所有拓扑。保留前方positive=0的snapshot，分别记录真实稀疏交通和后处理稀疏context，后者不能代替前者。可用ROUTES=明确XML_ID列表覆盖后续发现的缺失路口/merge/反向approach，再换SEED采集。

新增 --hv_snapshot_native_map_export 只增加独立native_map_lanes与metadata，不覆盖旧map_lanes或改变已有生成器条件。保存真实方向连接、width、XYZ、高程、map SHA、sim frame/time、actor bbox offset；未来dataset记录源SHA。采集输出 data/hv_init/coverage_时间戳/{sparse,normal}/raw。

“当前没有前方GT positive”“有限候选中没找到可行状态”“地图/route未知”和“已证明无可行解”必须区分。当前condition ledger明确保留前两类和unknown，不把零positive场景自动标成不可行。旧单帧数据也无法证明连续状态域无解。若要精确历史动态复现，新增采集还需独立CARLA recorder及完整控制/信号/参与者信息；本轮没有伪造旧历史。

## 下一版模型的状态

已提供 v6_condition：有向地图、width/XYZ、可达approach、独立actor tokens、明确0<x<=32/|y|<=32契约；GraphBuilder消费lanes_v6后保留连接，裁剪/重排后重新建立边，并按NuPlan的receiver约定编码pred/succ。旧记录没有lanes_v6时保持原图行为。

这些是数据与条件基础，不是已经训练好的V6。宽度/高程保存在condition中，尚未接入原AE固定维度；actor tokens尚未接入新的交互生成头，前方契约也不会让旧checkpoint自动受约束。

顺序应是：复现GT → 量化旧V5与有向approach覆盖差 → 检查真实占位与raw spawn → 补缺失Town/拓扑/初始化稀疏交通 → 新head显式参数化前方域并使用actor tokens → 小样本S1过拟合与GT上界 → 按episode分割训练 → 完整同口径评价。不要先启动长训练来掩盖配对、地图或候选支持域错误。

几何API依据CARLA官方说明：[Python API](https://carla.readthedocs.io/en/latest/python_api/)、[Bounding boxes](https://carla.readthedocs.io/en/latest/tuto_G_bounding_boxes/)。它们支持世界坐标bbox及level box读取，但没有把外包围盒相交定义成精确mesh碰撞。
