# P1→P2 后续一体化执行说明（2026-10-19）

## 严格边界

- 适用仓库 `2150016-njl/multi_adv_rift_scenario_dreamer_betop`、CARLA 0.9.15、RIFT Python 3.8；只针对服务器**实际已有**的冻结 capsule：`p1_frozen_capsule_occupancy_joint_20261019_034017_031802`，源码 SHA `ed27a2b78ffc7c3e6159db85d5756ff2ad9bfef754e79043225d343f5840854f`。
- 不替换活动 `hv_v8/p1_native_audit.py`；不改 GT、ego route、s 阈值、原始 pose、RIFT config 或原历史输出。不因 Model3 raw spawn 拒绝自动判错；也不因 `p1_pass=true` 自动宣称固定车型可行。
- `inputs`、`report`、`p2-export`、`test_p1p2_offline.py` **不访问 CARLA**。`p2_topology_probe.py` 仅读当前 world/map，不切图、不 spawn、不 tick。只有 `run95` 会用已有冻结 auditor 加载 Town、尝试 spawn/清理；必须在真正独占实例上运行。
- 95 条 `p1_calibration95.jsonl` 不等于历史 P2 的 **110 个前方 GT**。`p2_topology_probe` 是有向车道连接性基线，不是 P2 的完整 approach 构建，不计算 `110` 的 recall，不证明物理合法状态覆盖。
- Python 3.8 兼容：源码和测试无内置泛型运行时求值问题，均有 `from __future__ import annotations`。本地是 Python 3.13 的离线集成测试；服务器需使用其 Python 3.8 解释器再次执行以证明运行时兼容。

## 5. 从真实审计产出逐条+逐目标账本（纯离线，失败也做）

```bash
RUN_DIR=$(sed -n 's/^P1_FULL95_RESULT_DIR=//p' "$RUNLOG" | tail -n 1)
if [ -z "$RUN_DIR" ]; then
  RUN_DIR=$(sed -n 's/^P1_FULL95_RUN_DIR=//p' "$RUNLOG" | tail -n 1)
fi
if [ -z "$RUN_DIR" ]; then
  echo 'NO_RUN_DIR_EVIDENCE: cannot analyze absent audit; inspect launcher log'
else
  REPORT_DIR="$BASE/p1_95_ledger_$(date +%Y%m%d_%H%M%S)_$$"
  "$PY" "$ROOT/hv_v8/p1p2_pipeline.py" report \
    --root "$ROOT" --audit "$RUN_DIR/audit" --report-dir "$REPORT_DIR"
fi
```

生成 `p1_95_ledger.json`、`p1_95_ledger.csv`、`p1_95_targets.csv`。

看四个科学指标：

- `P1_NATIVE_95_VERIFIED`: 每条 native/map/route/GT 正例/坐标子证据，并要求可信 manifest/snapshot 绑定。
- `P1_CALIBRATION_95_COMPLETE`: 还要求全 95 条 occupancy 含完整人口、完整清理与确定结论，不允许任何 `unknown` 混成 completed。
- `P1_RAW_SPAWN_ACCEPTED/REJECTED/UNKNOWN`: 真实负例必须原样保留。
- `P1_MODEL3_LEGAL_TRAINING_READY=False`: 目前回放只验证生成请求/部分 pose，没有证明完整三维物理联合合法。即便 occupancy `complete` 也不自动成为固定 Model3 合法正例。

## 6. 主线下一轮研发的实际准入判断

- **可立刻进行**：P2 从 CARLA 真地图构建有向 lane/connector 图，基于 `ego_route` 提取地图条件的冲突锚点，验证路网方向。`p2-export` + `p2_topology_probe` 是工作起点，不是完成版 P2。
- **必须追加，而非此包声称完成**：对固定 **110 个历史前方 native-positive GT** 建立准确来源清单；把有向 lane 连接升级为显式 connector/crossing/merging 的 conflict anchor + 上游可出生区间；逐条解释漏召回，并基于同一 denominator 评估 ≥95% / ≥99% 支持域目标。
- **P3**：对经支持域判定的 GT 做 `(approach,s,d,Δyaw,v)` 编码解码回环，分开报告 geometrically reconstructable 与 Model3-spawn-verified。
- **P4 不能立即宣称正式启动**：需要 P2/P3 完整门槛，以及独立构建的固定 Model3 合法生成初始状态正例（生成前的 z/车型几何契约，失败后不得抬高 z 或重采样）。

最后：本交付只新增工具/诊断报告，不覆盖已验收的任何 capsule；所有输出写入不重复的新路径。真实 CARLA 的运行结果仅能从你服务器终端/日志得到，本地集成测试不得作为 CARLA PASS。
