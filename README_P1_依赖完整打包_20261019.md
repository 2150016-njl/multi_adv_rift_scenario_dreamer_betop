# P1 完整依赖打包：修复 `No module named hv_v8.common`

## 直接原因（已经由真实 traceback 确认）
旧 `p1_prepare_worldfix.py` 只将 `p1_native_audit.py` 和 `p1_world_guard.py` 拷贝到新的 capsule；原审计源码有 `from .common import ...`，新 capsule 没有 `hv_v8/common.py`。`importlib.util.find_spec` 只看模块入口文件存在，**不执行模块导入**，所以旧启动器的检查没有发现缺失依赖。该报错发生在 Python 启动阶段，不构成 P1 数据任何通过/失败证据。

## 修复范围
- 不更改科学源文件 `p1_native_audit.py`（SHA `b6036d51d849d0e0aa46c1dc35754e4be9f81ec35dd504146f6cf877ec88a6bb`），不更改地图/路由/native/物理阈值。
- 建立**新** `p1_frozen_capsule_world_transition_depcomplete_v2_20261019`；从实际旧 capsule（优先）或仓库 `hv_v8/common.py`（备选）复制 `.common`；复制已锁定 world guard，创建 `__init__.py`，记录依赖文件 SHA/provenance。
- 新启动器 `p1p2_pipeline_depcomplete.py` 首先核验模块和依赖 SHA，在实际审计 Python 子进程环境执行 `import hv_v8.p1_native_audit/common/p1_world_guard` 和 `python -m hv_v8.p1_native_audit --help`，**在创建新审计目录和连 CARLA 之前**发现同类打包失败。
- 旧 capsule、旧运行目录、manifest、snapshot 完全不修改。 `--real` 真正审计仍有 World/Town/episode/RIFT 的科学门槛；**本补丁绝不意味着 P1 全量 PASS**。
